4.	PRINCIPES DES TRAITEMENTS PIM-OF :
A partir d’informations reçues de Baan, PIM doit générer s’il le peut:
- la COOR à blanc
- l’ITR 
- La complétude de la COOR (phases, IHM, …)
- Les RM pour les FRM associés à l’ITD
Si PIM ne le peut pas, PIM engendre un message d’avertissement vers une ou plusieurs Boites aux Lettres (BAL) Lotus Notes, aucune création n’est générée et le processus devra être relancé depuis Baan.

PROCESSUS ATTACHES A MQSERIES :






























1)	OF de BAAN : Mqséries appelle PIM (BAPIM100.ksh) si au moins 1 enregistrement à traiter.
2)	BAPIM100.ksh boucle sur les enregistrements non traités de MQREC et pour chacun d’eux, 
3)	écrit un enregistrement dans PM11 . 
4)	Le script GOTxyPPN est un script périodique qui boucle sur les enregistrements dont le code interface est BAPIM1000 dans PM11 et assure le processus de création de COOR, ITR, RM et mesures à blanc. Le lancement de plusieurs BAPIM100 est sérialisé afin d’éviter la saturation machine qui pourrait avoir lieu si plusieurs générations COOR et ITR tournaient en même temps.
5)	GOTxyPPN  envoie dans MQENV, les OR à transmettre à TRAPE.
6)	GOTxyPPN  en fin de traitement TRAM, delete le PM11 traité.
7)	GOTxyPPN  lance ensuite le GOTxyPQN qui fait exclusivement de la MAJ dans TRAM.

DECOUPAGE DE L’INTEGRATION :
Le découpage est justifié par le fait les MAJ de TRAM et GIT se font sur 2 instances oracles différentes et que GIT ne peut donc pas mettre à jour les phases de la COOR avant que TRAM est exécuté le commit de son côté. Le découpage assure la cohérence des données dans les 2 applications et chacune des parties pourra être relancée en cas de problème.
Phase 1 : Récupération des enregistrements à traiter par l’interface : GOTxyPCN. Les enregistrements de la table MQREC dont le CODINF est ‘BAPIM100’ sont positionnés à traités en fin de traitement.
Phase 2 : L’intégration des données est subdivisée en 2 parties :
Partie 1 ( GOTxyPPN ) pourra être relancé manuellement depuis PIM :  
Partie 2 ( GOTxyPQN ) pourra être relancé depuis une DDT : GOTPQN .
Le choix d’avoir 2 scripts différents plutôt que d’avoir 2 niveaux dans d’un même script permet d’identifier rapidement le processus de relance en cas de plantage.
Appel PIM : 
L’appel du script CMTPIM00.ksh est assuré par un process Mqséries suite à une écriture dans la table mqrec.
PHASE 1 : Lecture de la table mqrec par BAPIM100.ksh :
Ce script se trouve sous l'arborescence suivante : /appl/pim/#/script/GOTxyPCN/script
	# = 'test' pour sv0125-e, 
   =  'simu' pour sv0125-ap, 
   =  'oper' pour l'opérationnel

- Boucle sur la table MQrec dont le code message (T$CODE ) = ‘BAPIM100’ et dont le statut du message est à non traité (T$STAT = ‘N’ )
- Positionne l’enregistrement à ‘T’
- Stocke les données dans la table interfaces DTM – TRAM ( PM11 ).

Gesfic 970 : NOUVELLES TYPOLOGIES D’ARTICLES
Dans la COOR :
type article 0 : la référence attendue est la référence EDD
type article X: la référence attendue est le PNT en standard.
Si couple Famille Moteur/Repère avec Type article X est présent dans la table applicative‘CTR’ alors la référence attendue est la référence EDD
type article Y : la référence attendue est le PNT
type article Z : la référence attendue est le PNT en standard.
Si le « Triplon » Ligne produit du Composé/Générique du composé/Repère est présent dans la table applicative ‘DEF’ alors le type article du composant doit être considéré comme X au lieu de Z, impliquant que si de plus le couple Famille Moteur/Repère est présent dans la table applicative‘CTR’ alors la référence attendue est la référence EDD
type article W : la référence attendue est la référence article en NDD
Rem EDD du composé = AABBGGGnnnn où
‘AA’ de AABB = Ligne produit du Composé
‘GGG’ = Générique du composé
‘nnnn’ = Unit du composé
