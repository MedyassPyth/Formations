2.2	PRINCIPE DE GESTION DE LA CONFIGURATION DES REFERENCES PM :
2.2.1	Exposé du problème :
Les nomenclatures PM répliquées vers PIM sont constituées de différents types de références :
 - "0" : EDD - Etat De Définition 
 - "1" : Si aucun des autres cas
 - "2" : Article ULC 
 - "3" : Article EMS/EMP (qui peut être à alternatives)
 - "4" : Article besoin 
 - "5" : Article besoin ( à alternatives )
 - "6" : Article de remplacement
 - "7" : Kit
 - "8" : Article variable ( sans repère fonctionnel )

Les EDD : Ces références sont assimilables à des numéros d’exemplaires qui peuvent porter sur une même définition.
Les articles de gestion : Ces références sont des références génériques qui permettent d’effectuer des traitements en fonction du type de composant qui leur est associé.
Les PEM : Ce sont les constituants élémentaires de la nomenclature.
Les EMS/EMP, ULC et KIT sont des sous définition composées de PEM, et éventuellement d’articles de gestion.

Il est à noter que certains articles de gestion n’ont pas de repères fonctionnels dans PM. 

Les nomenclatures PM sont générées plusieurs fois vers PIM avec des états de définition qui varient dans le temps ( non gelées, gelées, regelées )
Le dégel d’une référence PM se fait uniquement dans PM. Le regel génère un nouveau snapshot

 

2.2.2	Gestion de la configuration des nomenclatures en définition : 
* La configuration en définition NDD d’un OD se gère uniquement pour les EDD : 
Lors de l’intégration des nomenclatures PM dans PIM, les écarts d’attributs qui font évoluer une définition d’EDD, ( OD module ) sont les propriétés de composition :
- Le repère
- La référence du composant
- La quantité

Remarque : Etant donné que la référence du composant est un attribut de définition, dès qu’une référence PM évolue, les références utilisatrices multi-niveaux évoluent.

* La configuration en définition LRD se gère  pour les EDD, EMS/EMP et KIT : 
Lors de l’intégration des nomenclatures PM dans PIM, les écarts d’attributs qui font évoluer une définition de LRD sont les propriétés de composition :
- Le repère
- La quantité
Remarque : Etant donné que la référence du composant n’est pas un attribut de définition, l’évolution d’une LRD est mononiveau.

Pour un EDD existant, dès que l’OD module évolue pour changement de composition de repère ou de quantité, la LRD évolue.

 * La règle PM est que toute évolution de composition d’un EMS/EMP , ULC, KIT ou Composé à cumul de quantité entraîne la création d’un nouvel article.
Donc, lors de l’intégration dans DTM, si la référence article existe déjà, la définition reçue doit avoir la même composition en terme de repère, quantité au repère.
Gesfic 2069 : FEB concernant la modification de compo KIT ou EMS/EMP sans changement référence : Il est possible de conserver la même reference de tête si et seulement si les repères et les quantités sont strictement identiques. Un changement de référence ou l’ajout d’une solution autorise la conservation de la référence.

Les propriétés hors composition, ayant évoluées sont prises en compte   dans DTM.

* Pour les types d’articles différents de 0 ( EDD ) , 2 ( ULC ), 3 ( EMS/EMP ) et 7 ( Kit ) ayant une composition, ils sont considérés comme des composés à alternatives, donc toute nouvelle définition de composition reçue, annule et remplace celle connue de DTM.
Les propriétés hors composition, ayant évoluées sont prises en compte (1) dans DTM
 

2.2.3	Gestion de la configuration des nomenclatures en réalisation : 
Au moment de la constitution d’une COOR ( à la génération de l’ITR ), les propriétés de définition des composants sont ramenés dans la COOR pour les considérer comme référence durant la vie de la COOR . Ceci à pour effet que si un nouveau snapshot vient modifier les propriétés de définition, ceci n’aura aucune conséquence sur l’encours. Par contre à la génération d’une nouvelle ITR portant sur la même définition , la COOR associée prendra en compte les nouvelles propriétés de définition ( sous réserve d’acceptation qualité ) .

2.2.4	Définition du vocabulaire utilisé :
2.2.4.1	Les concepts PM : 
2.2.4.1.1	Référence PM : 
C’est la rubrique référence composant  «  REFCOMP » contenu dans le snapshot, sachant que la tête d’arborescence est appelée également au titre de «  REFCOMP» sans avoir de composé associé.
La notion de gel ne s’applique qu’aux EDD.
2.2.4.1.2	EDD : 
PM génère le fichier de nomenclatures NOMPIM00 à partir d’EDD : Ces références EDD sont des N° d’exemplaires de la définition : Dans le fichier NOMPIM00, un EDD est identifiable par son type de composant qui est égal à ‘0’. 
Afin de géré de manière unique la définition d’un ensemble d’EDD qui portent sur la même définition, on a créé un nouveau type de référence appelé OD module. 
A partir d’un EDD, on en déduit son produit générique ( PCA), son N° d’exemplaire ( N° d’ordre ) et sa définition ( OD module ) .











Un EDD est dit gelé, lorsque la rubrique PARTNB ( Part Number ) est renseigné. Dans le cas contraire, il est dit non gelé.
Remarques :
2 EDD peuvent porter sur 1 même définition mais cette définition n’est pas pour autant gelée ou non gelée pour les 2 EDD. C’est le lien N° d’ordre qui porte l’état de gel ou de non gel de l’EDD.

 

2.2.4.2	Les concepts DTM : 
2.2.4.2.1	OD : 
C’est la référence PM pour les articles dont le type est différent à 0
2.2.4.2.2	OD module : 
L’OD module est donc une référence générique de composants communs de même définition.
L’OD module est une référence aveugle définie par :
- L’applicabilité dans la table ‘ODM ‘ de la ligne produit pour un générique donnée.
Son radical est composé 
- D’un Bureau de Définition ( 2 caractères )
- D’un compteur
- D’une lettre clé
Le regroupement des N° d’exemplaires communs en terme de définition se fait manuellement par une table applicative ( table ODM ) .
L’OD module subit les règles d’évolution de gestion de configuration. 

2.2.4.2.3	PCA et N° d’ordre : 
C’est le découpage de la structure d’un EDD qui est nécessaire pour rattacher cet l’EDD à l’OD module.
Le PCA est la référence générique contenue dans l’EDD .
Le N° d’ordre est la concaténation des autres notions restantes


Notions PM :
Soit l’EDD : 10R0J7A0050
Générique: J7A
Ligne produit : 10
Type : R (valeurs possibles A/R/D /E ( Avionnage / Référentiel / Développement / Exceptionnel)
Unit : 0050

Notions DTM :
PCA : J7A
N° d’ordre résultant :  10R00050

 

2.2.4.2.4	Repère fonctionnel :
Le repère est une entité qui est issue de PM . 

2.2.4.2.5	LRD  : Liste De Repères

La liste de repères est gérée pour les EDD, les EMS/EMP et les KITS.
Elle est l’entité de gestion de configuration pour la composition de repères fonctionnels issus de NDD comparables en terme de définition et qui ont les mêmes repères fonctionnels et les mêmes quantités à chacun des repères. 
De plus, elle intègre les repères de niveau inférieur de la NDD pour lequel on rend les composants de 1er  niveau fictif ( cas des ULC et composant à cumul de quantité ).
 La liste de repère fait abstraction des repères composants fictifs « ULC ».

L’identifiant de la liste de repère est composé :
D’un radical alimenté par le radical de l’OD module ou la référence  de l’EMS/EMP ou KIT
D’un ‘/’
D’un indice numérique de 3 caractères.

 

2.3	GESTION COMMUNE DE 2 TYPOLOGIES DE DEFINITIONS PM :
Par anticipation des évolutions PM qui seront appliquées pour les nouveaux produits, il est nécessaire de faire cohabiter 2 types de définitions qui seront envoyées par PM.

Les notions de définition présentant 2 typologies possibles sont :
- Les composants à alternatives 
- Les composants à cumul de quantité
- Les composants à quantité variable

2.3.1	Les composants à alternatives :
D’une part, des composants à alternatives qui ont des composants, objet de la liste de choix dans la COOR à travers PIM. (cas 1).
D’autre part, la disparition des composants à alternatives et le rattachement direct au composé, des composants, objet à la liste de choix dans la COOR. Chacun d’eux possède un identifiant d’alternative au repère (cas 2).

2.3.1.1	Méthode proposée : 
Cas 1 :
- La référence de l’article de gestion ayant un repère fonctionnel dans PM de type 4, 5 ou 6 est chargée en l’état dans la nomenclature DTM.
- La quantité est celle issue de PM.
- Son type d’immatriculation est ‘C’ : Composant à alternative. 
Avantages :
- Dans DTM on sait quel article de gestion est utilisé pour constituer la liste d’alternatives.
- En COOR (à travers PIM) si le type de composant est 4, 5 ou 6 on affiche un libellé générique « ALTERNATIVE ».
- Les composants de l’article de gestion sont directement rattachés au composé : Ils ont chacun un lien d’équivalence.

Cas 2 : 
Lors de la rupture de repère, si le composant est déclaré comme étant en alternative, pour le composé traité :
- Création d’une première ligne de composition ayant comme référence article la référence générique « ALTERNATIVE ».
* La quantité associée est la somme des quantités au repère (une seule ligne du repère porte la quantité)
* Le type d’immatriculation est ‘C’ : Composant à alternative.
* Le type de quantité est ‘A’ : Quantité à contrôler par rapport à la quantité prévue.
- Les composants déclarés en alternative se voient affecter un lien d’équivalence.
* La quantité associée est celle issue de PM.
* Le type d’immatriculation est ‘E’ : Sans immatriculation.
* Le type de quantité est ‘C’ : Sans contrôle de quantité.
- Les composants de l’article de gestion sont directement rattachés au composé : Ils ont chacun un lien d’équivalence.

Méthode de traitement proposé :
A la création des définitions PM dans DTM les OD portent 2 visas : Le visa ‘R’ et le visa ‘Q’

Le fait qu’une propriété de suivi en utilisation ou relevé montage ou code classement soit modifiée à par conséquences 
- D’AVERTIR LA QUALITE DU CHANGEMENT D’ATTRIBUT
- De stocker la ou les nouvelles valeurs dans des rubriques de mise en réserve
- De retirer le visa ‘Q’ de l’OD impacté.
La qualité devra alors statuer sur l’application des attributs proposés par PM et viser ‘Q’, l’OD concerné. 
Action Qualité à réaliser :
Par un code opération réservé Qualité, l’utilisateur pourra accepter la nouvelle définition ou la refuser :
S’il l’accepte, les nouveaux attributs sont pris en compte dans l’OD, le visa ‘Q’ est apposé et les nouveaux attributs sont répercutés sur les COOR déclarés en écart à la génération de la COOR.
S’il la refuse, les nouveaux attributs de définition sont supprimés et le visa ‘Q’ est apposé. 

Attention : 
Cette procédure ne s’applique pas pour les COOR générées avant la modification d’attribut :
 S’il est nécessaire de prendre en compte les nouveaux paramètres dans une COOR existante, je propose ce que l’on appelle, un changement de composition par recopie . …on l’on recopie l’ensemble de la COOR avec les nouvelles propriétés de définition : SU, SM, Classement, alternatives …
